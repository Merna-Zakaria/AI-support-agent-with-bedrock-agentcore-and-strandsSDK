# Purpose of this Folder

This folder should contain the scaffolded project files to get a student started on their project. This repo will be added to the Classroom for students to use, so please do not have any solutions in this folder.



Reflection
Design decisions. The choice I thought hardest about was routing loyalty pricing through the AgentCore Code Interpreter rather than computing it in Python inside the tool. Nova-2-Lite is perfectly capable of describing a discount policy, but the arithmetic here compounds — points floor to 500-point blocks, cap at 50% of the order, and the tier percentage applies to the post-redemption subtotal, not the original total. Letting the model reason about that chain invites plausible-looking wrong numbers, which is the worst failure mode in a support context because nothing flags it. Running the rules as deterministic code in a sandbox with clearContext=True means every invocation starts clean and produces the same answer for the same inputs. I kept a tier-only fallback so a Code Interpreter outage degrades to a partial but honest answer rather than a hard failure, and tagged the output with calculation_method so downstream logs show which path ran.

A concrete challenge. My first working version of invoke() created the Agent inside the MCPClient context block but awaited agent.invoke_async() after it. Local tools worked; anything touching the Gateway failed intermittently with a closed-session error. The tool objects returned by list_tools_sync() are handles to a live MCP session, so exiting the with block tears the session down while the agent still holds references. The fix was moving both construction and invocation inside the block. A related bug took longer to spot: MemoryHook reads event.agent.state.get("actor_id"), and I had not passed state= to the Agent constructor. The hooks fired, found nothing, and returned silently — memory simply never persisted, with no error anywhere. I added logging inside both callbacks before I found it, which is the lesson: hooks that fail quietly need instrumentation from the start.

Production consideration — cost and latency. MemoryHook.__init__ calls get_namespaces(), which hits the Memory service on every single request just to fetch two static namespace templates. Under load that is one wasted network round-trip per turn plus its latency on the critical path. In production I would fetch the strategies once at module import and cache them, refreshing on a TTL, since strategy definitions change on the order of deployments rather than requests. The same argument applies to AgentCoreBrowser, which I instantiate per invocation and which is the most expensive tool in the list.
